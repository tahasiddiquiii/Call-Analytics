# Goals

## The goal

Build a system that turns call transcripts into **correct, faithful, machine-readable records** using a small local model, and show **how its quality was checked**. The brief says: *"We assess your judgement … A small, well-judged submission is better than a large one."*

## Requirements from the brief, and their status

| # | Requirement | How it is met | Status |
|---|---|---|---|
| 1 | One record per call with summary, intent, outcome, sentiment, action items, insights | `CallRecord` in `callanalytics/schema.py` | Done |
| 2 | Each record carries `call_id` = file name without `.txt` | Set by code from the file name | Done |
| 3 | All records in one JSON file in top-level `outputs/` | `outputs/records.json` | Done |
| 4 | Same structure, fields and formats in every record | Pydantic schema; failed calls still get every key | Done, tested |
| 5 | Structure described in the README | README "Output format" + `schema/record.schema.json` | Done |
| 6 | Output generated by the system, not edited by hand | Produced by the final run (`reports/final_run.log`) | Done |
| 7 | Designed for filtering/counting and for other software | Fixed category lists, booleans, versioned schema, `needs_review` | Done; `scripts/summarise.py` shows it |
| 8 | One command, folder in, JSON out | `python -m callanalytics data/calls` | Done |
| 9 | Works on any call file in the format | Robust parser; edge-case tests; 2 held-out calls | Done |

## How the work is scored, and what was aimed at

| Area (points) | Aim | Result |
|---|---|---|
| Output quality (35) | Correct, faithful records; traps handled | Intent 10/10, outcome 8/10, facts 28/32, references 5/5, 7/8 trap tests |
| Reliability (20) | Never crashes; doubt is flagged, not hidden | Failed-record path, `needs_review`, atomic writes, exit codes, tested |
| Verification and process (15) | Hand labels, scores per version, before/after evidence | 4 scored versions, bake-off, determinism, manual review |
| Engineering (15) | Clear structure, one command, tests | 8 small modules, 30 tests, Python 3.9 and 3.15 |
| Findings (10) | Specific, cited by call | 6 findings on slide 3, each naming its calls |
| Communication (5) | Short and clear | 5 slides, one-page write-up |

## Non-goals

- Not a production deployment: no scheduler, queue or dashboard. The CLI and exit codes are designed so one could be added.
- Not tuned to maximise the score on these 10 calls: the answer key was frozen before tuning, and known weaknesses are reported rather than over-fitted.
